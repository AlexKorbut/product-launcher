# Архитектура

Продукт — это ночной конвейер (pipeline), который превращает «сигналы интересов + поток новостей»
в свёрстанную газету. Запускается по расписанию (например, в 05:00 по таймзоне пользователя),
чтобы к утру PDF был готов.

## Конвейер: 8 стадий

```
[1] Сбор сигналов        Telegram, Instagram, RSS, онбординг-опрос, закладки
        │                       ↓ нормализация в единый формат «сигнал интереса»
[2] Профиль интересов    темы + именованные сущности + вектор интересов (embeddings)
        │
[3] Поиск кандидатов     RSS, новостные API (NewsAPI/GDELT), Telegram-каналы — МНОГО ЯЗЫКОВ
        │                       ↓ сотни статей-кандидатов
[4] Ранжирование+дедуп   релевантность к профилю, кластеризация дублей, разнообразие тем
        │                       ↓ 20–40 финальных историй
[5] Суммаризация+перевод Claude: пересказ + перевод на язык читателя + газетный стиль
        │
[6] Редакторская сборка  выбор передовицы, секции (Мир/Технологии/Бизнес/Культура),
        │                 размеры заметок, заголовки, врезки, подписи
[7] Вёрстка+рендер       HTML/CSS + Paged.js → headless-браузер → print-ready PDF
        │
[8] Доставка             Telegram-бот / email с PDF + ссылка на веб-версию (+ опц. печать)
```

Подробно стадии [2] и [3] разобраны в [03-interest-parsing.md](03-interest-parsing.md),
стадия [7] — в [04-newspaper-layout.md](04-newspaper-layout.md).

## Стадия 1 — сбор сигналов (ingestion)

Каждый источник — отдельный «коннектор», приводящий данные к единому формату.

- **Telegram.** Через user-аккаунт по протоколу MTProto (библиотека Telethon). Читаем каналы и чаты,
  которые пользователь читает сам, его реакции и пересланные сообщения. ⚠️ Юридический нюанс ниже.
- **Instagram.** Через официальный Graph API ограниченно (в основном свой контент); подписки и
  сохранённые посты надёжнее брать через ручной экспорт данных (Instagram Data Download) или
  периодический логин. На MVP — опционально/позже.
- **RSS / newsletters.** `feedparser`, плюс приём почты на отдельный адрес для рассылок.
- **Онбординг-опрос и явные интересы.** Пользователь отмечает темы, добавляет источники, пишет
  «что мне интересно» текстом.
- **Закладки/лайки** в самом продукте (обратная связь, стадия обучения профиля).

> **Юридика и ToS.** Парсинг Telegram через user-аккаунт допустим для **личного** потребления
> (пользователь подключает свой аккаунт к своим данным), но это серая зона ToS Telegram и риск
> банов/лимитов. На MVP — действуем от лица пользователя с его согласием и явным OAuth-подобным
> подключением; не масштабируем единый аккаунт на всех. Контент СМИ пересказываем и ссылаемся на
> оригинал (fair use / дайджест), не перепечатываем целиком. Эти решения зафиксировать с юристом
> до публичного запуска.

## Стадии 2–6 — обработка (где живёт AI)

- **Профиль интересов** хранится как: (а) список тем с весами, (б) именованные сущности (люди,
  компании, команды, страны), (в) вектор интересов (embedding) для семантического матчинга.
- **Отбор и ранжирование** — гибрид: векторное сходство (embedding кандидата vs профиль) + правила
  (свежесть, источник, разнообразие) + лёгкая LLM-переоценка топ-кандидатов.
- **Суммаризация, перевод, заголовки, редакторские решения** — модели Claude (раскладка по моделям
  и стоимости — в [06-tech-stack.md](06-tech-stack.md)). Ночной прогон не требует низкой задержки,
  поэтому используем **Batch API (−50% к цене)** и **prompt caching** для общих системных промптов
  (стиль издания, правила вёрстки).

## Стадия 7 — вёрстка

HTML/CSS — единственный практичный способ получить газетную типографику с колонками, переносами и
разбивкой на страницы, который при этом легко рендерится в PDF. Движок постраничной разбивки —
**Paged.js** (поддерживает `@page`, многоколоночность, висячие строки, колонтитулы), рендер —
headless-браузер (**Playwright/Chromium**) → PDF. Каждый стиль газеты = набор CSS-переменных + SVG
шапки (masthead) + правила сетки. Детали — в [04-newspaper-layout.md](04-newspaper-layout.md).

## Стадия 8 — доставка

- **Telegram-бот** — основной канал (логично, раз источники тоже Telegram): присылает PDF файлом +
  ссылку на веб-версию. Он же — точка онбординга и обратной связи (кнопки «больше такого»/«меньше»).
- **Email** — PDF во вложении + веб-ссылка.
- **Веб-версия** — адаптивный HTML того же контента (для чтения с телефона).
- **Печать по требованию** (фаза 2/3) — отправка print-ready PDF в API типографии (Newspaper Club /
  Mixam) с доставкой бумажной газеты.

## Оркестрация и инфраструктура (высокоуровнево)

```
                ┌─────────────┐
   расписание → │  Scheduler  │  (cron / Temporal / Celery beat) на 05:00 в TZ юзера
                └──────┬──────┘
                       ↓ запускает «выпуск» (issue) для каждого пользователя
   ┌───────────────────────────────────────────────────────────┐
   │  Workers (очередь задач)                                    │
   │  ingest → embed → retrieve → rank → summarize → layout      │
   └───────────────────────────────────────────────────────────┘
        │              │                 │
   Postgres        Object store      LLM (Claude API,
   + pgvector      (S3: PDF,         Batch + caching)
   (профили,        картинки)
    статьи,
    embeddings)
```

Конкретные технологии и обоснование — в [06-tech-stack.md](06-tech-stack.md).
