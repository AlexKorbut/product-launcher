# Как парсить интересы человека

Это ядро персонализации. Задача: из «что человек читает» получить машинно-понятный **профиль
интересов**, по которому можно отбирать новости из любых источников на любом языке.

## Источники сигналов и что из них берём

| Источник | Сигнал | Сила сигнала |
|----------|--------|--------------|
| Telegram — каналы, на которые подписан | темы каналов | средняя (подписка ≠ активное чтение) |
| Telegram — что пересылает / реагирует | явный интерес | **высокая** |
| Telegram — текст личных/групповых чатов | темы разговоров | средняя, но приватная — обрабатывать осторожно |
| Instagram — на кого подписан | интересы/персоны | средняя |
| Instagram — сохранённые/лайкнутые посты | явный интерес | **высокая** |
| Онбординг-опрос | явные темы | **высокая**, но статичная |
| Текст «что мне интересно» | явные интересы | высокая |
| Обратная связь в продукте (👍/👎, дочитал) | уточнение | **высокая**, динамическая |

## Модель профиля

Профиль — это три слоя, дополняющие друг друга:

1. **Темы с весами** — таксономия (например: `технологии/ИИ`, `геополитика/Ближний Восток`,
   `спорт/велоспорт`, `бизнес/стартапы`). Веса 0..1, растут от сигналов.
2. **Именованные сущности** — конкретные люди, компании, команды, страны, продукты
   (`Anthropic`, `Tour de France`, `ECB`). Позволяют ловить узкие интересы, которые тема не покрывает.
3. **Вектор интересов (embedding)** — усреднённый/кластеризованный вектор контента, который человек
   потребляет. Нужен для **семантического** матчинга новостей, которые не попали ни в одну тему/сущность.

Зачем все три: темы дают объяснимость и контроль (пользователь видит и правит свои темы), сущности
ловят специфику, embedding ловит «похожее по смыслу» без жёсткой категоризации.

## Конвейер построения профиля

```
сырые сигналы (посты, подписки, тексты)
        │
   [дедуп + чистка]            убираем шум, рекламу, служебные сообщения
        │
   [тегирование]              дешёвая LLM (Haiku) или классификатор: пост → темы + сущности
        │                      ↳ батчами через Batch API (−50%)
   [эмбеддинги]               embedding каждого значимого сигнала (Voyage AI, мультиязычный)
        │
   [агрегация]                накопить веса тем, частоты сущностей; кластеризовать эмбеддинги
        │
   ПРОФИЛЬ: {темы:веса, сущности:частоты, вектор(ы) интересов}
```

- **Тегирование** — недорогая операция на больших объёмах, поэтому модель попроще (Haiku 4.5) +
  Batch API. Промпт: «отнеси текст к темам из таксономии и извлеки сущности», structured output (JSON).
- **Эмбеддинги** — у Anthropic своего embedding-эндпоинта нет; используем **Voyage AI**
  (рекомендованный Anthropic), мультиязычная модель — она кладёт текст на разных языках в одно
  пространство, что критично для многоязычного отбора.
- **Холодный старт** (нет истории): полагаемся на онбординг-опрос + текст «что интересно» + 5–10
  стартовых источников. Профиль уточняется обратной связью первые дни.

## Многоязычность: ключевая деталь

Чтобы «находить релевантное на разных языках», и **запрос (профиль)**, и **кандидаты (новости)**
должны жить в одном семантическом пространстве. Поэтому:

- эмбеддим мультиязычной моделью → испанская статья и русский интерес сопоставимы напрямую;
- сущности нормализуем (алиасы: `ЕЦБ` = `ECB` = `Banco Central Europeo`);
- язык **вывода** (газеты) задаёт пользователь; язык **источников** — любой, перевод на стадии 5.

## Непрерывное обучение

Каждый выпуск даёт сигналы: что дочитали, что отметили 👍/👎, какие секции открывали в веб-версии.
Эти сигналы корректируют веса тем и подмешиваются в вектор интересов (с затуханием старого, чтобы
профиль следовал за изменением интересов). Раз в неделю — пересборка/перекластеризация профиля.

## Приватность

- Тексты личных чатов — самый чувствительный сигнал. По умолчанию: обрабатывать только для извлечения
  тем, **не хранить** сырой текст дольше необходимого, дать тумблер «не использовать личные чаты».
- Профиль и эмбеддинги — данные пользователя; экспорт и удаление по запросу (GDPR/CCPA).
- Никогда не класть секреты/PII в долгую память LLM-агентов.
